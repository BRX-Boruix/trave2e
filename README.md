# trave2e

BORUIX 的**目录遍历权限验收程序**，验证一条容易被忽略的访问控制规则。

[English](README.en.md)

## 测什么

规则是：**目录如果没有"可进入"权限，里面的文件即使是"人人可读"的，也访问不到。**

访问一个文件其实是两步——先沿路径**逐级进入**每层目录，再访问文件本身。第一步需要目录上的可进入
权限；如果中间某层目录不让进，后面的检查根本轮不到，文件自身权限再宽松也没用。

程序构造两个**对照夹具**，用同一个非属主身份分别测试：

| 夹具 | 目录权限 | 文件权限 | 期望 |
| --- | --- | --- | --- |
| 对照组 | `0755`（可进入） | `0644` | 能访问 |
| 实验组 | `0700`（不可进入） | `0644` | **被拒绝** |

两组唯一的变量是**父目录有没有可进入权限**，文件权限完全相同。因此实验组被拒而对照组成功，就
证明拒绝确实来自目录检查。要求返回的错误必须是"权限不足"，而不是"文件不存在"。

## 一个被推翻的设计

程序最初的设计是：降权 → 由属主修改权限 → 再降权验证。**这个设计必然失败**，原因是它触到了一个
重要的安全属性：

**一旦降低了权限，就再也提不回来。** 权限不足的进程可以继续往下降低自己，但不能往上提——否则
任何程序都能自我提升为管理员。所以"先降权，再以高权限去改东西"走不通。这不是缺陷，而是权限模型
正确工作的证据。

改正后只降权一次，降权前把所有夹具准备好，之后同时验证两侧。这反而让对照更干净：两次检查发生在
**同一身份、同一进程、同一时刻**。

程序最后还会**主动尝试提权并期望被拒绝**——这是预期内的拒绝，不是失败。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 全部通过 |
| 非零 | 首个失败项编号 |

## 测试夹具

```
/scratch/trave2e_dir/    # 0755，对照组
/scratch/trave2e_nx/     # 0700，实验组
```

> 程序最后会打印"身份无法从此处恢复"——这是**设计如此**，不是故障。

## 构建

```bash
cargo build --release
```

由 shell 内建命令 `trave2e` 拉起。

## 文件结构

```
trave2e/
├── Cargo.toml    # 包定义
├── build.rs      # 注入链接脚本
├── linker.ld     # 用户态段布局
└── src/
    └── main.rs   # 夹具构造与两侧验证
```
